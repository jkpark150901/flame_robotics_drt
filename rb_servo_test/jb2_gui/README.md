# 동시 관절 이동 GUI — servo / jb2

```bash
./rb_servo_test/jb2_gui/run.sh
```

프로젝트 venv를 사용한다. `PYTHON=/path/to/python`으로 변경 가능.

1. 시작 자세와 목표 자세 J1~J6를 deg로 입력. **현재 자세 읽기**로 시작 자세를 채울 수 있다.
2. 필요하면 경유 자세 J1~J6를 입력하고 **추가**. 선택한 행의 뒤에 삽입되며, 선택이 없으면 맨 뒤에 추가된다. **선택 수정/선택 삭제**, ↑/↓로 순서 변경 가능.
3. jb2 전체 분할 수(기본 100) 또는 servo 주기(기본 10ms), 속도, 가속도를 설정하고 미리보기.
4. 명령 모드 `servo` 또는 `jb2` 선택. servo는 gain/alpha, jb2는 blending 값을 사용.
5. **모션 실행**. 시작 자세로 move_j 이동 후, 경유 순서대로 목표까지 한 번 실행한다.

모든 관절은 하나의 6관절 벡터로 함께 명령한다.
시작→경유1→경유2→…→목표의 각 구간을 균등 분할한다.
jb2는 전체 N개 점을 구간 길이에 비례해 배분하고 각 구간에 최소 1개를 할당한다. servo는 아래 시간 샘플링을 사용한다.
모든 경유점과 최종 목표는 정확히 포함한다. 시작점은 별도로 등록하지 않는다.
연속한 동일 자세는 입력 오류로 처리하지만 시작=최종 목표인 왕복은 허용한다.

**찍턴 예시:** 시작 `0 0 0 0 0 0`, 경유 `30 15 -10 20 5 -15`, 목표 `0 0 0 0 0 0`.
모든 이동 관절이 경유점에서 방향을 바꾸고 처음으로 돌아온다.
일부 관절만 반전하려면 경유점 이후 해당 관절만 반대 방향으로 설정한다.
이론 프로파일과 servo 시간표는 각 사용자 경유점에서 전체 속도 0으로 연결하며, 정지 유지시간은 추가하지 않는다.
jb2는 중간 대기 없이 전체 점을 한 목록으로 실행하므로 실제 경유점 도달/감속은 blending에 따라 달라진다.

## 시간과 모드

- **jb2**: 동일 N개 점을 `move_jb2_add(point, speed, accel, blend)`에 등록한 후 한 번 실행.
- **servo**: 공간 분할 수와 독립적으로, 가감속 프로파일을 짧은 시간 주기로 샘플링해 목표를 생성한다.
  GUI **Servo 주기 [ms]** 기본값은 10ms (범위 2~200ms). 각 경유 구간의 끝을 정확히 포함하기 위해
  구간 시간을 ceil(T/주기)개로 나누므로 실제 계획 간격은 설정값 이하의 거의 일정한 값이다.
  120° / 50°/s / 100°/s²는 정확히 10ms × 290구간, 첫 목표 0.005°, 등속 구간 목표 간격 0.5°.
  각 주기 시작에 다음 목표를 보내며 t1=계획 간격, t2=GUI의 Servo 유지시간 값(기본 0.1초)이다. 마지막 추가 목표에도 동일 값을 적용한다.
  gain/alpha는 입력값을 사용한다. 끝에서 목표를 한 번 더 보낸다.
  Python/TCP와 ACK 대기 때문에 실제 10ms를 보장하지는 않는다. 과도한 지연은 실행을 중단하며
  `servo_schedule.csv`에 계획/실제 전송 시각을 저장한다(중단된 경우 전송 시도 기록도 보존).
  명령 주기와 t2는 독립적이다. 기본 t2=0.1초는 저장소 rbpodo 예제 설정을 사용한다. 제어기/펌웨어별 허용 범위는 실제 응답으로 확인해야 한다.

점선은 시작/각 경유/종료에서 정지하는 이상적인 속도·가속도 프로파일이다. 회색 세로선은 이론 경유 시각이다.
max_joint는 D=max(|Δq|), l2는 D=||Δq||₂를 사용하며
`vp=min(V,sqrt(A*D))`, `ta=vp/A`, `T=D/vp+ta`로 계산한다.
관절 속도는 스칼라 속도에 Δq/D를 곱한다. servo의 전송 시간표에도 선택한 기준을 사용한다.
jb2 내부 blending, jerk, 하드웨어 한계를 재현하는 공식은 아니다.
실측은 실선이고 시작 시각만 맞춘다. J1~J6 체크박스로 여러 관절을 동시에 선택하며 전체 선택/해제를 지원한다.
관절별 색상은 고정이고 같은 관절의 이론은 점선, 실측은 실선이다. 기본은 6관절 모두 표시한다.
그래프 툴바로 시간 축 확대/이동 가능.

simulation은 지령각 jnt_ref, real은 엔코더각 jnt_ang를 분석한다. 두 각 모두 원본에 저장한다.
실기는 모드 선택 및 확인 체크가 필요하다. 입력 자세의 충돌/관절 범위는 자동 검증하지 않는다.
실험 중 speed bar=1.0이며 종료 후 idle이면 기존 모드/배율 복원을 시도한다.

**웨이포인트 근접도:** 위치 그래프에 시작·경유·목표 자세를 ○(이상 도달 시각)로, 실측이 그 자세에 가장 가까이 간 지점을 ×로 표시한다.
jb2는 실제로 보낸 분할점도 작은 점으로 표시한다. 거리는 시간과 무관하게 6관절 공간에서 실측 경로(샘플 사이를 선분으로 이은 꺾은선)와 웨이포인트의
최단 거리이며, 웨이포인트는 지정한 순서대로 경로를 지나는 것으로 배정한다(순서를 지키는 범위에서 거리 합 최소, 시작=목표인 왕복도 구분됨).
코너를 깎으면 경유점 거리가 커진다. 저장: `waypoint_proximity_<n>.csv`(시작·경유·목표), jb2는 `command_points_proximity_<n>.csv`(분할점, 1000개 이하),
`summary.csv`에 `waypoint_max_dist`, `waypoint_max_joint_error`, `via_max_dist` 열. 열: ideal_time_s(이상 도달), closest_time_s(실측 최근접 시각),
dist_L2_deg(6관절 L2), max_joint_error_deg, target/closest/error(측정-목표) J1~J6. servo는 분할점(주기마다 보내는 목표)은 저장하지 않는다.

`out/<timestamp>/`에 설정, 실제 웨이포인트, 원본 기록, 속도, 관절별 최고속도/종료 오차,
현재 선택한 관절들의 그래프를 저장한다. 저장 결과 열기는 이 GUI 형식을 읽고 경유 목록도 복원한다. 경유 목록이 없는 이전 직선 실험도 읽을 수 있다.
중지 버튼은 task_stop을 요청한다. 부분 기록은 저장하고 미완료 모션은 결과 분석에서 제외한다.

## 전송 시각 ↔ 제어기 응답 ↔ 실제 모션 비교

버튼 **전송·모션 타이밍** (또는 `python timing_plot.py out/<폴더> [--zoom 시작 길이]`)은 명령 전송(TCP)·제어기 응답·측정 모션을 한 시간축(벽시계, 0 = 모션 명령의 첫 송신)에 겹쳐 그린다.
실행이 끝나면 자동으로 `timing_compare.png`(전체), `timing_zoom.png`(servo: 첫 1 s 확대), `timing_compare.csv`를 결과 폴더에 저장한다.

- **servo**: 위 = 측정 속도, 가운데 = 송신 틱(파랑)과 제어기 응답(ACK) 도착 틱(주황), 아래 = 송신 간격·응답 도착 간격 [ms]와 응답 지연(응답 − 송신).
- **jb2**: 위 = 측정 속도(점선 = 제어기 Info `motion_changed` 응답이 온 시각), 가운데 = `move_jb2_add` 송신 틱, `move_jb2_run` 송신, 구간 시작 Info(◆, msg 900, 901 …)와 종료(■), 아래 = Info 간격으로 본 구간 지속 시간.
  `move_jb2_add` 는 모션 전에 한꺼번에 보내므로 **송신 주기는 jb2 에서 의미가 없고**, 모션 중에는 제어기가 알아서 실행한다.
- 새로 기록하는 폴더는 `follow.csv` 의 `wall_time` 열, `servo_schedule.csv` 의 `wall_call`/`wall_return`, `jb2_schedule.csv`(명령별 송신 호출·반환 시각)를 같은 시계로 남겨 **정렬이 정확**하다.
- 이전 형식 폴더는 정렬을 추정한다(송신 = 응답 도착 − 상대 시각의 중앙값, 모션 = `robot_state` 3 이 된 시각을 Info 응답에 맞춤). 그래프 제목에 "추정 정렬"이 표시되고, 정렬 방법에 의해 값이 정해지는 응답 지연과 "모션 시작까지 시간"은 표시하지 않는다.
- 측정한 것은 **PC 가 보낸 시각과 제어기가 응답한 시각**이다. 네트워크 카드에서의 실제 패킷 시각이 필요하면 `sudo tcpdump -i <인터페이스> -w x.pcap host 10.0.2.7 and port 5000` 로 캡처해야 한다.

검증:
`PYTHONPATH=rb_servo_test/jb2_gui venv/bin/python -m unittest discover -s rb_servo_test/jb2_gui`

종료 대기 중에도 제어기 응답을 수신하여 지연 오류를 확인한다. `responses.json`에 응답 원문, `error.json`에 실패 단계와 마지막 servo 파라미터를 저장한다. 모드/배율 복원 실패도 별도로 기록한다.
