# Rainbow 외부 스크립트 통신 테스트 GUI

프로젝트 루트에서 실행:

```bash
python rb_servo_test/external_script_gui/app.py
# 초기 접속 주소 지정 (화면에서도 변경 가능)
python rb_servo_test/external_script_gui/app.py --ip 192.168.0.10 --port 5000
```

Python 3와 tkinter만 사용합니다. Ubuntu에서 tkinter가 없다면 `sudo apt install python3-tk`로 설치합니다.

1. 전문을 바이패스할 서버의 IP와 TCP 포트(기본 5000)를 입력하고 **연결**을 누릅니다.
2. 목표 관절각 J1~J6을 **도 단위**로 입력합니다. **현재 입력 추가**로 여러 웨이포인트를 표에 넣습니다. 행 선택 시 입력창에 불러오며, 입력 변경 후 **선택 행 수정**으로 반영합니다. 삭제 및 ↑/↓ 순서 변경도 가능합니다.
3. **입력값 단일 전송**은 위 관절각 입력값을 한 번 보냅니다. **웨이포인트 전체 실행**은 표의 위에서 아래로 모든 점을 실행합니다. 실행 시작 시 관절각과 설정값을 복사하므로 실행 중 편집은 다음 실행에 적용됩니다.
4. 오른쪽 로그에서 TX / RX 원문 바이트, HEX, 바이트 수, 시각을 확인합니다. 로그는 선택·복사 및 저장할 수 있습니다.

## 웨이포인트 실행

### 실행 방식

- **Move J:** 속도·가속도를 지정해 각 점에 `move_j(..., 1)`을 보내고 완료 응답(`The command was executed`)을 기다린 뒤 다음 점으로 이동합니다. 응답 제한 시간(기본 120초)을 넘기거나 거부/오류 응답이 오면 후속 전송을 중단합니다.
- **Servo J:** 점 2개 이상을 등록한 후 Servo 패널의 Speed·Accel·t1/주기·t2·Gain·Alpha를 설정합니다. 첫 점으로 `move_j(..., 1)` 이동 후 완료 응답을 기다리고, 이후 구간은 `move_servo_j(...)`를 주기적으로 전송합니다. t1은 전송 주기와 같으며 기본 0.02초(50Hz)입니다. 주기는 0.002~0.1초, t2는 주기 이상이어야 합니다.
- 각 Servo 구간은 6개 관절이 함께 도착하는 사다리꼴(짧은 구간은 삼각형) 속도 프로파일입니다. **각 관절의 지령 속도 ≤ Speed, 지령 가속도 ≤ Accel**로 보간합니다. 각 웨이포인트에서 속도 0으로 감속한 뒤 다음 구간으로 이동하므로 방향 반전 시에도 가속도 제한을 지킵니다. 블렌딩 없이 모든 점을 통과합니다. 동일한 연속 점은 생략합니다.
- 구간 시간을 전송 주기의 정수배로 늘려 정확한 끝점을 전송하고, 마지막 목표를 2회 더 보내 마지막 지령 속도를 0으로 만듭니다. 실행 상태에 진행률을 표시하며 모든 TX/RX는 기존 raw 로그에 남습니다.
- 전송은 GUI와 별도인 통신 스레드에서 단조 시계 기준으로 예약합니다. 응답 수신 때문에 주기마다 100ms씩 지연되던 통신 루프도 개선했습니다. 계획보다 `max(50ms, 주기×2)` 이상 늦어지면 밀린 지령을 한꺼번에 보내지 않고 중단합니다. 일반 데스크톱 OS와 TCP이므로 하드 실시간 전송은 보장하지 않습니다.
- **웨이포인트 전송 중단**은 후속 지령만 중단합니다. 실행 중 수동 명령은 차단하며 **Task Stop**은 전송 실행을 취소한 뒤 `task stop`을 보냅니다. 연결 해제 역시 후속 전송을 중단합니다. 이미 전송한 모션의 정지나 실제 최종 도달을 보장하는 기능은 아닙니다.

속도·가속도 제한은 생성한 지령 프로파일의 값입니다. 실제 로봇의 추종 성능은 제어기 모드·서보 설정·통신 지연에 따라 달라지며, 이 툴은 상태 포트나 실측 피드백으로 속도·가속도·도달 여부를 검증하지 않습니다.

기존 `../rb_ext_script_demo.py`, `../servo_follow.py`의 외부 스크립트 형식을 따릅니다.

```text
move_j(jnt[0,0,0,0,0,0], 10, 20)
move_servo_j(jnt[0,0,0,0,0,0], 0.02, 0.04, 0.1, 0.5)
```

기본 끝 문자는 LF(`\n`)이며 CRLF 또는 None을 선택할 수 있습니다. 직접 입력 전문은 공백·줄바꿈을 보존한 뒤 선택한 끝 문자를 추가합니다. 자동 응답 파싱이나 공백 제거를 하지 않습니다. `b'...'` 표기의 `\r`, `\n`, `\x00` 등으로 제어문자도 확인할 수 있으며 HEX는 수신 바이트를 그대로 나타냅니다.

TCP 수신 로그 한 건은 `recv`가 반환한 청크입니다. 한 응답이 여러 RX로 나뉘거나 여러 응답이 합쳐질 수 있습니다. TX는 소켓 전송 성공을 의미하며 로봇의 명령 승인이나 모션 완료 여부는 RX를 통해 확인해야 합니다. 실시간 로그는 약 20,000줄로 제한되므로 필요한 로그는 미리 저장하세요.

지정한 서버에 외부 스크립트 전문을 그대로 전송합니다. Simulation / Real 모드 선택이나 `pgmode` 자동 전송은 없습니다. 서버에서 로봇으로 전문을 바이패스하고 응답을 반환하면 됩니다. 웨이포인트 실행 시 첫 Move J 및 순차 Move J는 기존 로봇 응답(`The command was executed`)을 기다리므로 해당 응답도 서버에서 그대로 전달해야 합니다. 직접 스크립트는 별도 탭에 있습니다. 상태 포트 5001을 추가로 연결하거나 로봇 상태를 조회하지 않습니다.
