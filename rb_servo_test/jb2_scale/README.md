# jb2 관절 이동량 스케일 실험

GUI와 별개로 `experiment.py`를 실행한다. 시작 자세 → 목표 자세 한 구간을
`move_jb2_clear()`, `move_jb2_add(target, speed, accel, 0, 0)`, `move_jb2_run(0)`으로 보낸다.
각 케이스 시작 자세로 이동할 때만 기존 실행기의 `move_j`를 사용하며, 이 이동은 속도 분석에서 제외한다.
blend=0으로 고정해 먼저 단일 구간의 속도 기준을 확인한다. 다중 구간 blending 효과는 이 실험 범위 밖이다.
보간/DTW/GUI 설정은 사용하지 않는다. targets.csv의 시간 열은 파일 형식용이며 jb2에 전달하지 않는다.

기본 진폭 30°, 속도 10°/s, 가속도 20°/s²:

| 케이스 | ΔJ1, ΔJ2 | 최대 이동 관절 기준일 때 J1/J2 속도 | L2 기준일 때 J1/J2 속도 |
|---|---|---|---|
| single | 30°, 0° | 10, 0 | 10, 0 |
| equal | 30°, 30° | 10, 10 | 7.071, 7.071 |
| unequal | 30°, 15° | 10, 5 | 8.944, 4.472 |
| swapped | 15°, 30° | 5, 10 | 4.472, 8.944 |

두 예측 모두 관절들이 같은 진행률로 동기화된다는 가정이다. 실제 제어기가 이 중 하나를
사용한다고 미리 단정하지 않는다. 관절 자체 제한, 속도 override, 가감속, 기록 속도의 영향을 확인해야 한다.
단일 관절 케이스는 설정 속도 대비 실제 속도를 보는 대조군이다. 필요하면 `--scales 0 1 0 0 0 0` 등으로 각 관절 대조군을 추가한다.

프로젝트 루트에서 실행한다. 아래 0 자세는 **목업 예시**이다.

```bash
# 연결 없이 계획과 목표 자세만 확인
venv/bin/python rb_servo_test/jb2_scale/experiment.py --base 0 0 0 0 0 0

# 목업: 실제 제어기 속도 규칙은 재현하지 않으며 통신/분석 검증에만 사용
venv/bin/python rb_servo_test/jb2_scale/experiment.py --base 0 0 0 0 0 0 --mock --execute
```

실제 제어기에서는 `--base`에 검토한 시작 자세 J1~J6 [deg]를 입력하고,
`--ip 제어기주소 --execute`를 추가한다. 기본은 제어기 simulation 모드이며 jnt_ref를 기록한다.
실제 엔코더 속도 실험은 `--real --real-ack`를 추가한다. 각 케이스가 끝나면 simulation으로 돌아간다.
실기 speed ≤30, accel ≤60으로 제한해 기존 실행기의 자동 상한 적용으로 실험 조건이 달라지지 않게 한다.
계획 파일에 시작/목표 자세가 기록되며 충돌이나 관절 가동 범위를 자동 검증하는 기능은 없다.

`--amplitude 30 --speed 10 --accel 20`으로 크기/속도/가속도를 변경한다.
`--cases equal unequal`로 일부 케이스만, `--scales 1 0.5 0.25 0 0 0`으로 임의의 6관절 비율을 실험한다.
각 케이스는 같은 base에서 출발하고 마지막 케이스 후에는 그 목표에 남는다.

결과는 기본 `rb_servo_test/jb2_scale/out/<timestamp>/`에 저장된다.

- `plan.json`: 명령 조건, 실제 목표, 두 가설의 예상 속도
- `summary.csv`: 관절별 최대속도, L∞ 최대속도, L2 최대속도, 최대 부근 유지 시간
- 각 실행 폴더의 `follow_*.csv`: 원본 측정각 및 시각
- `speed_trace.csv`: 측정각, 시간 창 차분 속도, 원시 차분 속도
- `speed_metrics.json`: 설정 속도, 예상 속도, 실제 속도, 동일 시각의 관절별 속도
- `speed.png`: 시간에 따른 이동량 및 관절별/L2 속도

기본 속도 계산은 0.1초 창 차분이며 `--velocity-window`로 변경할 수 있다. 원시 차분 최대값도
함께 저장해 필터링 효과를 확인한다. 기록은 기본 100 Hz 요청이며 실제 수신 시각으로 미분한다.
`near_peak_s`는 L∞ 최대의 95% 이상 구간 누적 시간이다. 짧으면 삼각 속도 프로파일일 수 있어
속도 기준을 결론내리기 어렵다. `plateau_resolved`는 그 시간이 max(0.3초, 창 길이의 두 배) 이상인지
나타내는 참고 표시이며, 제어기 정상속도 도달을 보증하지 않는다. 그래프에서 평탄 구간을 확인한다.
