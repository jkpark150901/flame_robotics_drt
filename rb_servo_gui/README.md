# RB Servo Tracking Tool

Rainbow Robotics 협동로봇의 **외부 스크립트(TCP 5000/5001)** 로 `move_jb2_add` / `move_servo_j` 궤적 추종을 시험하고,
추종 성능을 원본 궤적과 비교해 주는 GUI 입니다.

- 입력: 웨이포인트 CSV(보간 자동; `J1..J6`[deg] 형식과 플래너 출력[rad] 형식 자동 인식) 또는 보간된 CSV
- 실행: 서브샘플링 → `move_jb2_add` / `move_servo_j` 추종 → 측정각·추종 시간 기록
- 분석: DTW(순서 보존) 매칭쌍 기준 오차, 매칭 전/후 그래프, 판정(PASS/FAIL), 실행 간 비교용 `summary.csv`
- 모드: **simulation(기본)** / **real(확인 절차 필요)** / 로봇 없이 테스트하는 내장 목업

## 설치 / 실행

Python 3.9 이상, tkinter 필요 (Linux 는 `sudo apt install python3-tk`).

```bash
pip install -r requirements.txt     # numpy, scipy, matplotlib
./run.sh                            # Windows: run.bat   (설치 없이 바로 실행)
# 또는 패키지로 설치 (pip 21+ / 빌드 격리 사용 시 최신 setuptools 자동 사용)
pip install .  &&  rb-servo-gui
```

> setuptools 가 오래된(<61) 환경에서 `--no-build-isolation` 으로 설치하면 메타데이터를 못 읽어 실패합니다. 이 경우 `./run.sh` 를 쓰세요.

로봇 없이 전체 흐름과 안전장치를 점검:

```bash
./run.sh --selftest                 # 모든 통신은 127.0.0.1 내장 목업
```

배포(Python 없는 PC): `packaging/build_exe.sh` 또는 `packaging/build_exe.bat` (PyInstaller, 빌드한 OS 용 결과물).

> **한글이 □ 로 깨질 때**: conda/ROS 환경의 `LD_LIBRARY_PATH` 가 시스템 Tk 대신 글꼴(Xft)을 못 읽는 다른 libtk 를 잡는 경우입니다.
> 프로그램이 이를 감지하면 `LD_LIBRARY_PATH` 없이 한 번 자동 재시작하고, `./run.sh` 는 처음부터 비워서 실행합니다.
> 한글 글꼴이 없으면 `sudo apt install fonts-noto-cjk`. 확인: `./run.sh --check-fonts`

## 사용 순서

1. **연결/궤적** 탭: 제어박스 IP(LCD 표시값), 궤적 CSV 선택. 처음에는 `examples/waypoints_robot1_short.csv` 로 시험.
   로봇이 없으면 "로봇 없이 테스트"를 체크하면 내장 목업에 연결합니다.
2. **실행/모션** 탭: 추종 방식(jb2/servo/both), 서브샘플링 간격, 속도·가속도, servo 파라미터 설정.
3. [궤적 미리보기]로 기준 궤적과 지령점 확인 → [▶ 실행].
4. **결과** 탭 (표와 그래프 사이 경계는 끌어서 폭 조절, 그래프 목록의 **★ 항목**은 관절 J1~J6 을 골라 화면에서 직접 다시 그리고, "속도 절대값" 체크로 속도를 크기(|v|) 또는 부호 있는 값으로 전환): 실행 폴더별 결과 표(추종 시간, 궤적 추종 오차 p95, 종료 각 오차, **속도 리플 / 횡방향 흔들림 / 거친 구간 비율**, 판정), 그래프(매칭 전/후, 시뮬레이션 기록), 판정 상세. 판정 기준은 **판정 기준** 탭에서 바꾸고 [다시 분석].

## 극값 기준 매칭 + 구간 DTW

분석은 먼저 관절별 최대/최소점을 검출하고 같은 관절·같은 극값 종류를 발생 순서로 대응시킵니다.
기본 최소 돌출도는 0.05deg, 허용 정규화 시간 차이는 0.35입니다(판정 기준 탭에서 변경).
극값의 높이를 같게 만드는 방식으로 상대를 고르지 않습니다. 대응 극값을 고정한 다음,
그 사이에서 시작/끝이 고정된 DTW를 수행합니다. 후처리에서도 극값 대응은 움직이지 않습니다.

6관절은 하나의 공통 시간 매칭을 사용합니다. 관절별 대응이 서로 교차하면 가장 많은
극값 대응을 유지하는 순서 일관된 기준점 집합을 선택하고, 나머지는 `order_conflict`로
기록합니다. 검출 기준을 넘는 상대 극값이 없으면 `reference_missing`으로 기록하며
임의의 대응값이나 0 오차를 만들지 않습니다. 돌출도 기준 미만의 극값은 검출 대상이 아닙니다.

결과 상세에 각 극값의 원본/측정 시각, 각도, 미도달량을 표시하고 그래프에 기준점을 ×로 표시합니다.
`compare_*_extrema.csv`와 분석 JSON에 동일 정보가 저장됩니다. 미도달량은
최대점에서 `원본-측정`, 최소점에서 `측정-원본`이며 양수=미도달, 음수=초과입니다.
`compare_*_dtw.csv`는 모든 DTW 대응쌍, 기존 `*_pairs.csv`는 측정 샘플당 한 대응점입니다.
기존 오차 합격 기준은 유지되며 극값 누락·순서 충돌은 별도 진단 항목입니다.

이전 결과는 **다시 분석**해야 새 매칭이 반영됩니다. 단순 그래프 재표시는 저장된 옛 매칭을 유지합니다.
`analysis.ordered_match`는 이전 문서·비교용으로 남아 있으며 실제 분석은 `matching.extrema_dtw`를 사용합니다.

## 그래프 시간축 조절

미리보기와 결과 그래프의 **시간축**에서 시작·끝 시간(초)을 입력하고 **적용**을 누릅니다.
시간 그래프 위의 마우스 휠은 포인터 위치를 중심으로 X축만 확대·축소하고,
**◀ / ▶**는 현재 구간 폭의 절반씩 이동합니다. **전체**로 처음 범위를 복원합니다.
같은 시간축의 패널은 함께 움직이며 Y축 범위는 유지됩니다.

DTW 그래프의 `matched reference time`(매칭 원본 시간)과 `tracking time`(실제 추종 시간),
프로파일의 원본 시간과 추종 시간은 시간축 목록에서 각각 선택합니다.
관절 선택을 바꾸어 다시 그려도 선택한 시간 범위는 유지됩니다.
기존 결과의 PNG 항목도 함께 저장된 CSV로 다시 그리므로 재분석 없이 조절할 수 있습니다.
원본 CSV가 없는 이전 결과는 이미지로 표시되며 시간축 조절은 비활성화됩니다.

## 극값 보존 샘플링

`step=10`은 기본 추출 간격입니다. 10개마다 한 점에 더해 각 관절의
방향 전환점(최대·최소), 정지 구간의 시작·끝, 전체 시작·끝을 반드시 포함합니다.
어느 관절에서든 필요한 시각이면 해당 시각의 6관절 자세를 함께 보존하므로,
실제 지령점 수는 기준 궤적의 1/10보다 많아질 수 있습니다.
보장은 입력 또는 보간된 **기준 샘플**의 극값에 대한 것이며, 샘플 사이의
연속시간 극값을 새로 계산하거나 실제 로봇의 정지를 강제하지 않습니다.
JB2 블렌딩과 servo 응답에 따라 실측 극값은 달라질 수 있습니다.

### servo 타이밍 (`servo_timing`)

- **`profile` (기본)**: 설정의 속도·가속도(`speed`, `accel`, jb2 와 같은 값)를 **관절 속도·가속도 한계**로 하는 이상 프로파일을
  원본(내삽) 궤적 위에서 만들고, 이를 **고정 주기 `servo_period`(기본 20 ms)로 시간 샘플링**해 보냅니다 (jb2_gui 의 servo 와 같은 전송 방식).
  - 한계: `max_joint` 는 관절마다 |속도| ≤ speed, |가속도| ≤ accel. `l2` 는 6관절 벡터 크기 기준.
  - 직선 경로에서는 사다리꼴(가속-등속-감속, `vp = min(speed, √(accel·L))`, `T = L/vp + vp/accel`)과 같습니다.
    굽은 곳·관절이 방향을 바꾸는 곳에서는 관절 가속도가 accel 을 넘지 않도록 **경로 속력을 줄입니다** (전진·후진 적분).
    시작·끝에서만 정지하고 중간 정지는 없습니다.
  - 전송: 프로파일 길이 `T` 를 `ceil(T / servo_period)` 개로 균등 분할(끝을 정확히 포함)하고, 목표 k 는 시각 k·dt 의 프로파일 위치,
    (k−1)·dt 에 전송, `t1 = dt`. `t2` 를 0 으로 두면 `2·dt` (20 ms 주기 → 0.04 s, 0.02~0.2 로 제한).
  - 서브샘플링(`step`)은 servo profile 타이밍에는 쓰지 않습니다 (jb2 와 original 타이밍에만 사용).
  - 계획보다 `max(50 ms, 2·dt)` 넘게 늦게 전송되면 실행을 중단합니다. 이때는 `servo_period` 를 늘리세요.
  - 실기에서는 `real_speed_cap` 으로 제한된 속도·가속도로 프로파일을 만듭니다.
  - 경로는 원본 샘플을 지나는 3차 스플라인으로 보간합니다 (직선 보간의 꺾임이 지령 가속도 튐이 되지 않도록).
  - **실제로 보낼 지령**(주기 샘플)의 차분 속도·가속도를 계산해, 설정을 넘으면 계획용 한계를 그 비율만큼 낮춰 다시 만듭니다.
    그래서 지령은 항상 speed·accel 이하입니다 (실행 로그와 `compare_*.json` 의 `cmd_speed_max`, `cmd_accel_max`, 계획에 쓴 `speed_plan`, `accel_plan`).
    궤적 A·B 에서 계획 가속도는 설정의 88~93 %, 실행 시간은 3~6 % 늘어납니다.
  - 지령이 한계 안이어도 실측은 제어기 응답(gain, alpha, t2)에 따라 조금 넘을 수 있습니다. 결과 탭 ★ 속도 프로파일의 가운데·아래 패널에서
    관절 최대 |v|, |a| (l2 기준이면 벡터 크기)를 설정선(빨간 점선)과 비교해 확인하세요.
- **`original`**: 기준(원본) 궤적의 시간 간격대로 지령점마다 전송합니다 (이전 동작).

**점선 = 이상 프로파일.** `profile` 타이밍이면 다음 그래프에 관절별 이상 위치·속도를 점선으로 겹칩니다.

| 그래프 | 점선의 시간 기준 |
|---|---|
| 실행 탭 [궤적 미리보기] 아래 패널 | 프로파일 시간 (회색 실선 = 경로 속력) |
| `sim_follow_*.png` (저장) | 첫 servo 지령 시각 = 0 |
| 결과 탭 ★ 위치/속도 프로파일, ★ 속도 프로파일 | 모션 시작 = 0 (위쪽 패널은 첫 지령 = 0, 점 = 보낸 지령점의 계획 도달 시각) |

실제 전송 기록은 실행 폴더의 `servo_schedule.csv` (계획/실제 전송 시각, 지령점 번호, t1, t2, 관절각)에 저장합니다.
이 프로파일은 이상적인 가정이며, 제어기 내부 보간이나 jerk 제한을 재현하지 않습니다.

## 실행마다 만들어지는 폴더

`<출력 폴더>/<시각>_[REAL_]<mode>_step<N>/`

| 파일 | 내용 |
|---|---|
| `config.json` | 요청한 설정 / 실제 적용된 설정(실기 속도 상한 등) |
| `traj_ref.csv`, `traj_sub<N>.csv` | 기준(보간) 궤적, 로봇에 보낸 지령 궤적 [rad] |
| `follow_<mode>_<시각>.csv` | 측정 기록 (첫 줄에 method/파라미터/기준 시각 JSON) |
| `sim_follow_*.png` | 측정 전체 타임라인 (관절각, 각속도, robot_state, 단계 구분) |
| `compare_follow_*_after.png` | DTW 매칭 후 비교: 원본과 측정, 궤적 추종 오차, 시간 변환 |
| `compare_*.json`, `compare_*_pairs.csv` | 지표·판정, 측정 샘플별 매칭쌍과 오차 |
| `surface_*.csv` | **링크 표면 오차**(URDF 지정 시): 시간별 최악 점 변위, Chamfer, Hausdorff [mm] |
| `velocity_*.csv` | 추종 속도 데이터 (관절별 속도 [deg/s, 부호 있음], 관절공간 속력). 그래프는 결과 탭의 ★ 항목에서 관절을 골라 그림 |
| `smooth_map_follow_*.png`, `smooth_*.csv` | 매끄러움 시각화: 경로 위에 국소 거칠기 점수를 색칠(1 = 기준). CSV 는 샘플별 점수 |

출력 폴더 바로 아래 `summary.csv` 에 실행마다 한 줄씩 쌓여 파라미터별 비교에 쓸 수 있습니다.

## 링크 표면 오차 (URDF, 선택)

설정의 **URDF** 칸에 로봇 URDF 를 지정하면, 추종 중 각도 오차가 **링크 표면에서 몇 mm 의 차이**로 나타나는지 계산합니다.
측정 자세와 DTW 로 짝지은 원본 자세를 각각 FK 로 배치해 링크 메시(표면 샘플점)를 비교하며, 같은 점끼리의 **최악 점 변위**를 주 지표로,
Chamfer 와 Hausdorff 를 함께 보고합니다. Chamfer 는 평균이라 최악 위치를 낮춰 보므로 단독으로 쓰지 마세요. 자세한 내용은 [docs/metrics.md](docs/metrics.md) 11장.
URDF 가 실제 로봇과 일치한다는 전제가 필요합니다. 이 저장소의 제어기 설정(`python/controller.cfg`)은 로봇을 `dda_rb10_1300e`(`urdf/rb10_1300e_DDA.urdf`)와
`rt_rb10_1300e`(`urdf/rb10_1300e_RT.urdf`) **두 대 모두 rb10_1300e** 로 두고 있고, 두 URDF 의 팔 기구학은 `urdf/rb10_1300e.urdf` 와 같습니다(링크 간 거리 차이 0.000 mm, 같은 메시).
따라서 6관절 팔 전용 궤적(`waypoints_robot*.csv`)에는 **`urdf/rb10_1300e.urdf`** 를 쓰면 됩니다. 단, 이는 설정 파일 기준이며 실물 로봇의 모델 표시나 관절 영점으로 확인한 것은 아닙니다.
(`rb20_1900es_RT` 는 더 큰 다른 팔이라 이 설정의 로봇과 다릅니다.)

### 메시 차이 보기 (결과 탭)

결과 탭의 그래프 목록에서 **★ 메시 차이 (URDF, 시점 선택)** 을 고르면 로봇 메시를 두 자세로 겹쳐 그립니다.

- 위쪽 **시간 그래프**(표면 차이 D·Hausdorff·Chamfer [mm], 관절 오차 [deg])를 **클릭하거나 드래그**해서 시점을 고르면, 놓을 때 그 시점의 메시가 갱신됩니다. [최악], [처음], [끝] 버튼으로 바로 이동할 수 있습니다.
- 아래쪽 메시: **색 = 같은 메시 점의 실제 변위(mm)**, 회색 반투명 = 기준(원본) 자세. 형상은 확대하지 않고 실제 크기(×1) 그대로이며, 화면의 **최악 점 변위**도 ×1 기준입니다. 오차가 mm 단위라 형상 차이는 거의 안 보이고 색과 수치로 읽습니다.
- 방위·고도 슬라이더와 [정면][측면][위][등각] 버튼으로 보는 방향을, **링크** 선택으로 한 링크만 확대해서 볼 수 있습니다. "색 범위 고정"을 켜면 시점이 달라도 같은 색 눈금으로 비교할 수 있습니다.
- URDF 는 그 실행의 설정에 기록된 것을 쓰고, 없으면 설정 탭의 URDF 칸 값을 씁니다. 표면 오차 시계열이 저장돼 있지 않은 실행은 화면을 열 때 자동으로 계산합니다(몇 초).
- 그림용으로 메시를 링크당 약 1800 삼각형으로 줄여서 그립니다. 변위 계산(지표)에는 쓰이지 않고, 지표는 표면 샘플점으로 계산합니다.

## 평가 기준 (시간 어긋남에 공정하도록 분리)

- **궤적 추종 오차 (DTW 매칭쌍 기준)**: 측정 샘플과 DTW로 짝지은 원본 위치의 6관절 L2 오차 (p95, 최대)
- **커버리지**: 원본의 모든 점이 측정 경로에서 가까운지 (구간을 건너뛰지 않았는지)
- **진행도 / 샘플 간 이동**: 끝까지 갔는지, 순간이동이 없는지
- **시작/종료 각 오차**: 시작 자세 오차, 그리고 마지막 안정 구간(마지막 0.3초 이상)의 최종 각 오차. 모션 종료 시점 판정(`reach_tol`)과 분리해서 따로 판정
- **추종 매끄러움**: 경로 자체의 비매끄러움(꺾임 등)은 감점하지 않도록 경로 모양과 무관한 양만 봅니다.
  - 속도 리플: 경로를 따라가는 속력(호길이 변화율)의 고주파 성분 RMS / 평균 속력
  - 횡방향 흔들림: DTW 매칭쌍 오차의 고주파 성분 RMS [deg] (원본 경로 모양은 쌍 오차에서 상쇄됨)
  - 정체 비율: 경로 중간(진행도 5~95%)에서 속력이 중앙값의 20% 미만인 시간 비율
  - 고주파 = 이동평균 창(추종 시간/10, 0.3~2 s)을 뺀 나머지. jerk 는 노이즈에 민감해 쓰지 않습니다.
  - 합격선 기본값(리플 15%, 흔들림 0.3°, 정체 2%)은 임의의 초기값입니다. 합성 데이터로는 이상적 추종(리플 3~6%, 흔들림 0)과 떨림/멈칫거림이 구분되고,
    시뮬레이션 실기록에서는 jb2 리플 8~47%, servo 약 29% 로 실행 조건에 따라 크게 달라졌습니다. 실제 허용 수준에 맞게 조정하세요.
- 타이밍 지연(늦음/빠름)은 참고 정보로만 표시하고 판정에는 쓰지 않습니다.

## 안전 (중요)

- 기본은 **simulation 전용**입니다. real 은 설정 파일에 저장되지 않아 항상 simulation 으로 시작합니다.
- **real 모드**: 로봇 모드를 `real` 로 고르고 [실행]을 누르면 사전 점검(현재 자세, 시작 자세까지의 이동량, 적용 속도)이
  표시되고, **E-Stop 확인 체크 + `REAL` 입력**을 해야 시작합니다. 로봇이 정지 상태(idle)가 아니면 시작하지 않습니다.
- real 에서는 속도 상한(기본 30 deg/s, 가속도 2배)이 적용되고, 실행 중 모드가 달라지면 즉시 중단합니다. 끝나면 simulation 으로 되돌립니다.
- **[중지]는 `task stop` 전송일 뿐 비상정지가 아닙니다.** 실기에서는 반드시 물리 E-Stop 을 손이 닿는 곳에 두세요.
- 이 도구의 real 경로는 실제 로봇에서 검증되지 않았습니다(내장 목업과 시뮬레이션 모드로만 시험). 첫 실기 사용은 낮은 속도로 하세요.

## servo 종료 오버슈트와 `t2` (관측)

시뮬레이션 기록에서 `move_servo_j` 의 마지막 지령 뒤 로봇이 **마지막 지령 속도 × t2 만큼 더 나아가 멈추는** 것이 관측됐습니다
(robot2, t2=0.2: 종료 오차 `[-0.97, 3.59, 0.80, -3.32, 1.74, -1.24]°` = 마지막 지령 구간 속도 × 0.2 와 6관절 모두 일치.
`servo_j_sweep_results` 의 1관절 램프에서도 오버슈트가 t2 에 거의 비례). 공식 문서에는 이 동작 설명이 없고, 실기에서 확인된 것이 아니라 시뮬레이션 기록 기반의 추정입니다.

- 설정 `final_hold`(기본 2): 마지막 점을 같은 값으로 더 보내 마지막 지령 속도를 0 으로 만듭니다. 목업(이 거동을 흉내 낸 것)에서는 종료 오차가 3.59° → 0.00° 로 줄었습니다. 0 으로 두면 이전 동작입니다.
- 같은 이유로 `t2` 가 크면 구간 중간에도 지령점보다 앞서 나갈 수 있습니다. `t2` 를 작게(0.02~0.05) 하고 `t1`≈명령 주기로 두는 시험을 권합니다 (`t1 + t2 ≥ 명령 주기`).
